# Color Lab

A color-mixing web app for a five-year-old. Pick two or three paints, watch them mix,
and hear the result read aloud.

**Live app:** https://nathangraves814.github.io/color-lab/

## What it does

- 24 paints. Mix two, three or four.
- Results come from a real subtractive paint model, not RGB averaging, so blue and
  yellow make green and the three primaries make brown.
- Every result is named and spoken out loud, so a child who cannot read yet can still
  use the whole app on their own.
- A 2/3/4 picker above the mixing slots sets how many paints go in, and hides the
  slots she is not using.
- Colors I Found saves every mix discovered. Missions give nine target colors to chase.
- Works offline once loaded, and installs to the iPad home screen as a full-screen app.

## How the mixing works

Each paint is stored as a pigment recipe: an RYB chroma vector plus separate white
(tint) and black (shade) amounts. Mixing averages the recipes, rescales the chroma so
the hue stays as strong as the paints that went in, converts RYB to RGB by trilinear
blending between eight tuned cube corners, then applies the tint and shade.

Repeating a paint is how a ratio is written: red, white, white, white is one red to
three white. Two things make those ratios behave like real paint (v1.6.0):

- **White and black are strong.** A paint's pull on the mix grows with how much white
  or black is in it, up to 1.5x for pure white or black (`TINT_STRENGTH`). One drop of
  black in three of red already makes crimson, and red + black alone goes to maroon.
  White and black are equal, so white + black stays a middle gray.
- **Opposites dull each other.** When the paints cancel toward neutral, the mix is
  pulled toward gray (`MUTE`). The pull is strongest for a small dose of the opposite
  (4 : 1, a quarter of the way to full cancellation) and fades as the dose grows, so
  four green and one red gives fern green, the muted green in Golden's 4 : 1 recipe,
  and four blue and one orange gives slate blue. Full cancellation is left alone, so
  red + yellow + blue, and any 1:1 pair of opposites, still makes brown. In RYB every
  1:1 pair of opposites is one part of each primary, so they all make the same brown.

Pure hues all have equal strength, so blue + yellow is still the textbook green. Real
blue overpowers yellow; making it stronger would move the 1:1 anchors the missions
depend on, so that is left as a decision for ratio mode.

Result names come from a list of 122 colours that walks the 12-hue RYB wheel (red,
vermilion, orange, amber, yellow, chartreuse, green, teal, blue, indigo, purple,
magenta) and gives each hue a tint, a shade and a muted tone, plus browns and neutrals.
The nearest name is found by CIELAB distance, with words a young child already knows
weighted slightly to win ties.

**A mix of two different paints can never be named after one of its own ingredients.**
Without that rule the nearest name for red + orange is "red", which teaches her nothing;
those names are struck from the running so the mix has to resolve to a third word
(vermilion). Mixing a paint with itself is not a mix, so it keeps its own name.

`tools/audit-colors.py` checks this over all 20,450 two-, three- and four-paint
recipes, repeats included, and reports how often each name comes up at each size. Piling on more
paints pulls mixes toward taupe, gray and dusty rose, which is expected pigment
behaviour, not a bug. It also replays counted recipes the way a ratio mode would build
them: every pair of paints at 4:1, 2:1, 1:1, 1:2 and 1:4 (1,380 recipes), with the
same ban, and prints the lesson ladders from section 8.5 of
`research/color-education-packet.md` so a name that contradicts the colour shows up.
The script exits non-zero if any mix is named after one of its ingredients.

## The voice

iOS Safari does not expose Apple's Enhanced or Premium voices to web pages, so live
`speechSynthesis` on an iPad is stuck with the compact system voice no matter what the
user has installed. The vocabulary here is finite, though (24 paints, 122 colour names and
ten phrases), so the app ships pre-rendered audio instead of synthesising anything.

`voice/` holds 278 AAC clips generated by Kokoro-82M, about 2MB, precached by the service
worker and played back through the Web Audio API. Each colour has two readings so the
hundredth mix does not sound like the first, and `speechSynthesis` remains as a fallback
if a clip fails to load.

Each tap names only the paint she just added. The answer is read when she fills the last
slot the recipe has room for, which depends on whether the picker is set to two,
three or four colours. Say it reads the whole recipe back: "Blue. Yellow. That's green!"

The generator refuses to build if any word has no pronunciation. misaki's dictionary does
not carry every colour name, and an unknown word becomes a placeholder that synthesises as
**silence**, so the clip says "That's ..." and stops without erroring. Three names hit this
(seafoam, terracotta, ochre); the `SPOKEN_AS` map in the generator feeds the synthesiser a
spelling it can say while the app keeps the real one. Add to that map if the build reports
a word it cannot pronounce.

To re-cut the pack in one of Kokoro's other 53 voices, see the setup notes at the top of
`tools/generate-voice.py` and run:

    .venv/bin/python tools/generate-voice.py --voice af_bella

Adding a single phrase does not need a full re-cut. `--only ui/four-colors.m4a` renders
just that clip and merges it into the existing manifest.

The script reads the word lists out of `app.js`, so the clips cannot drift from what the
app actually says.

## Versioning and updates

The build number is rendered faintly in the bottom-right corner. If a device does not
show the version you just deployed, it is still running an old build.

Two strategies share one service worker. The shell (html/css/js) is **network-first**, so
code changes reach a device on its next online load. The voice clips are **cache-first**,
since ~190 immutable files should never cost a round trip. The service worker is
registered with `updateViaCache: 'none'` and installs its shell with `{cache: 'reload'}`,
because a browser serving a cached `sw.js` (or a fresh worker installing a stale shell
through the HTTP cache) will otherwise pin a device to an old build indefinitely. When a
new worker takes over, the page reloads itself once.

To cut a release, bump **both** `VERSION` in `app.js` (what gets displayed) and `VERSION`
in `sw.js` (what names the cache). They are deliberately separate: the displayed string
lives in `app.js` so that it reports the freshness of the code actually running, not of
some other file that happened to load.

## Adding it to an iPad

Open the link in Safari, tap Share, then Add to Home Screen.

## Running it locally

Any static file server works. Under a sandbox that cannot read the launch directory,
`python3 -m http.server` fails at startup, so use the bundled one:

    python3 tools/serve.py 8127
